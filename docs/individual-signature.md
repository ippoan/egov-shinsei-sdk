# 個別ファイル署名形式 (手続 950A101220029000) — 構成と既知の課題

社会保険関係手続の一部 (e.g. `950A101220029000` = ＡＰＩテスト用手続（社会
保険関係手続）（個）１００１＿０１) は **個別ファイル署名形式** を採る。
通常の標準形式 (構成管理情報 1 ファイルに署名) と違い、申請書・添付書類を
それぞれ別の「構成情報ファイル」でラップし、各々に xmldsig 署名する。

このドキュメントは、e-Gov API 問合せ窓口との往復 (受付 #5370088) で判明した
構造と、現時点で未解決のエラーを記録する。一次資料 (往復メール原本) は
ref-files `egov-shinsei-sdk-spec` repo の `spec/*5370088*.eml` を参照。

## ファイル構成 (3 つの構成 XML + 本体 + 添付)

`/procedure/950A101220029000` のスケルトンは以下を含む:

| ファイル | 様式ID | 役割 | 申請種別 |
|---|---|---|---|
| `kousei.xml` | `999000000000000001` | 構成管理情報 (main) | 新規申請 |
| `kousei<ts>.xml` | `999000000000000009` | 構成情報 (申請書 / **WriteAppli**) | 申請書作成 |
| `kousei<ts>.xml` | `999000000000000001` | 構成情報 (添付書類 / **SignAttach**) | 添付書類署名 |
| `950A10122002900001_01.xml` | — | 申請書本体 | — |
| `Test.pdf` | — | 添付書類署名ファイル | — |

`configuration_file_name` の順序は `[main, SignAttach, WriteAppli]`
(様式ID で判別するのが確実: 9=WriteAppli, 1=SignAttach)。

## 5/7 e-Gov 提示サンプルの構造

### 構成管理情報 `kousei.xml` (申請種別: 新規申請)

`</管理情報>` 直後に **添付書類属性情報 4 件** を列挙する:

1. WriteAppli 構成情報 (`<添付書類名称>…の構成情報` / ファイル: WriteAppli の `kousei<ts>.xml`)
2. 申請書本体 (`<添付書類名称>` = 様式名称 / ファイル: `950A10122002900001_01.xml`)
3. SignAttach 構成情報 (`<添付書類名称>添付書類署名ファイル１の構成情報` / ファイル: SignAttach の `kousei<ts>.xml`)
4. 添付実体 (`<添付書類名称>添付書類署名ファイル１` / ファイル: `Test.pdf`)

### 構成情報 (申請書 / WriteAppli, 申請種別: 申請書作成)

`</構成情報>` 直前に `<申請書属性情報>` を置く:

```xml
<申請書属性情報>
  <申請書様式ID>950A10122002900001</申請書様式ID>
  <申請書様式バージョン>0005</申請書様式バージョン>
  <申請書様式名称>ＡＰＩテスト用手続（社会保険関係手続）（個）１００１＿０１</申請書様式名称>
  <申請書ファイル名称>950A10122002900001_01.xml</申請書ファイル名称>
</申請書属性情報>
```

### 構成情報 (添付書類 / SignAttach, 申請種別: 添付書類署名)

`</管理情報>` 直後に添付書類属性情報 (Test.pdf) を 1 件。

### 署名

検証用証明書 `e-GovEE01_sha2.pfx` (pw: `gpkitest`) で WriteAppli /
SignAttach の構成情報 XML に xmldsig 署名 → `/apply` に POST。

## 未解決のエラー (3 構造すべてで申請不可)

| 試行構造 | 返却エラー |
|---|---|
| 5/7 サンプル準拠 (WriteAppli に `<申請書属性情報>` あり) | 「構成管理情報の申請書属性情報は"申請書送信"の場合は指定することができません」 |
| WriteAppli から `<申請書属性情報>` 削除 | 「添付必須のファイル (…＿０１ / form_name) が添付されていません」 |
| SignAttach に apply 参照を追加 | 「指定された添付書類名称が必要」 |

→ `<申請書属性情報>` の指定可否と申請書本体の参照方法が噛み合わず、どの構造でも
通らない。5/15 に e-Gov へ「エラーが発生する申請データ一式」を送付し、回答待ち
(受付 #5370088、試験期限 5/31)。

## ジェネレータ

`scripts/generate-egov-payload.ts` が 5/7 サンプル準拠の申請データ一式
(= 上記 1 つ目のエラーを再現する構造) を生成する。e-Gov から正解構造の回答が
来たら、このスクリプトの構成ロジックを 1 箇所直すだけで全 27 手続に展開できる。

```bash
npx tsx scripts/generate-egov-payload.ts \
  --skeleton <skeleton-950A101220029000.zip> \
  --pfx <e-GovEE01_sha2.pfx> \
  --out ./egov-payload-950A101220029000
```

- skeleton / pfx は ref-files `egov-shinsei-sdk-spec` repo の `spec/` から取得
  (`folder_download_url` で一括 download 推奨)。
- `--pfx` 省略時は SDK 同梱のテスト PFX (test-apply.* と同値) を使用。
- 出力 zip を `/apply` に POST すると上記 1 つ目のエラーが再現する。
- 個人情報・申請者実値はベタ書きしない (テスト値のみ)。実送信時は
  生成後に申請者情報を差し替える運用。
